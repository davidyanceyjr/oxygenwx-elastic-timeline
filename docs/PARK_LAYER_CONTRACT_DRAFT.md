# Three-plane / supplemental-layer semantics — draft for OX-101 review

This is an owner-intent specification, **not** an adopted Kotlin/API, a shared image-plane compositor, or an installable scene-pack manifest. OX-101 is proposed to specify and test the ordering contract. OX-99 is proposed to wire the accepted base images into Living Urban Park's existing Compose Canvas only.

- Every world has three mandatory ordered planes: `BACKGROUND`, `MIDDLEGROUND`, `FOREGROUND`.
- Every plane has exactly one base scene image/drawable, and zero or more supplemental indexed layers (`layer-0` to `layer-N`).
- Painter order **within** a plane is `base`, `layer-N`, ..., `layer-1`, `layer-0`. `layer-0` is the *frontmost* supplemental layer in that plane, not the first item drawn.
- Painter order **between** planes is background entire plane, middleground entire plane, foreground entire plane. Thus `background-layer-0` is immediately behind the backmost drawn middleground content (normally its base), subject to transparency and effects. If there are no middle supplemental layers, the middleground base still exists.
- The order of fixed PNG and Kotlin/Compose elements at a given supplemental layer must be deterministic; define a stable tie breaker in OX-101 rather than relying on list iteration from arbitrary sources.
- Motion may travel across the viewport **without changing semantic depth**. Motion/interaction bounds are separate from layer clipping. Owner must approve explicit clipping rules for any element whose geometry spans the scene edge.
- Every element ID and its mutable animation state is scoped to its world; theme selection must not share mutable per-world element geometry.
- Forecast facts, selected Instant, source support and uncertainty remain app-owned, not supplied by theme assets. The theme owns appearance/geometry only.
- Missing/failed assets cannot leave partial activation or a blank screen; retain the previously supported world/fallback semantics.
- Keep this first proof separate from scene-pack manifest v2, which supports one First City canopy capability and one PNG; three-plane bundles require a separate versioned policy and budget decision.

## Architecture boundary and Park mapping gate

This plane contract concerns world-owned base artwork and supplemental scene depth. It does not define forecast facts, semantic weather tracks, light-phase decisions, theme selection, or timeline interaction. The Scene Generation draft describes a theme background and semantic weather layers; OX-101 must specify how its world-owned image bases and supplemental depth relate to that existing theme composition without renaming or replacing forecast-semantic layers. A weather layer may be placed within a world plane by the theme, but plane membership cannot alter weather meaning or selected-time ownership.

OX-05 established three depth groups in First City; OX-06 kept element identities First City-local. Neither establishes universal plane bases or a shared plane compositor. The generic `SceneElementDeclaration` carries IDs, passes, and geometry but does not supply those capabilities. OX-101 must not claim that a reusable compositor already exists. OX-99's review board must map the current Park passes—`BACKGROUND`, `MURAL_WALL`, `PARK_LANDMARKS`, `PATH`, and `FOREGROUND`—and each Park element to the proposed planes, marking each existing draw as retained, replaced, or suppressed. The source imagery and owner review determine the mapping; this draft does not guess it.

The map must include the app-owned live selected-time reading and the existing weather/unavailable rendering relative to every image plane. Source PNGs contain no forecast text. The owner-designated Concept 01 mockup is available and establishes intended placement: location on the tower, current temperature/condition plus owner-directed wind chill on the mural, wind on the banner, daily date/HI/LO/precipitation on the separate board, and daily cards in the bottom strip. The foreground source's blank board is the intended daily-summary surface; its exact text bounds and plane order still require measurement and approval. The owner selected the Streetcar Stop variant's hourly NEXT HOURS shelter allocation while retaining the separate daily board; the variant's three rows and sample values remain illustrative until the count/range is confirmed. Fixed sunlit artwork is visual reference material; owner approval must determine its use alongside supported-weather and unavailable states before OX-99 integration.

The three supplied transparent PNGs contain no streetcar shelter. The current app has a procedural `STREETCAR_SHELTER` draw but no forecast-sign surface. The owner-selected hourly content therefore still needs an explicit physical-art source/disposition and a sign treatment. Do not infer that the shelter is embedded in one of the base planes or that the procedural draw is retained.

## Reusability test

Park and one existing alternate world must share the **contract** but not a geometry registry, path, assets, transforms, weather decisions, or mutable element state. This is a draw-path architecture, not permission to accept executable behavior from downloaded packs.
