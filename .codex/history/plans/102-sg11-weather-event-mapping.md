## Shared contract and affected paths

Canonical hourly facts own an immutable collection of supplied typed event facts, each with stable WA identity, numeric source code when supplied, wording actually supplied when present, separate deterministic documented code description when applicable, and provenance. The optional primary references a member of the collection. Keep broad `conditions` and `phenomena` as scene/legacy inputs. Without a source primary, select the highest-ranked supplied identity using the complete owner-approved 47-ID order, independent of collection order and measurements; preserve all supplied events when choosing one display symbol. Forecast/accessibility wording and symbol derive from that same selected identity. Unknown, empty, or unsupported input never implies clear. The Open-Meteo sole supported event is primary.

`CatalogWindow`/`CatalogTimelinePresentation` own selected-`Instant` support and eligible carried-condition source-time evidence. `CanonicalForecastProjection` consumes that result; it must not independently choose a nearby fact or time. For legacy broad `CLEAR` and `PARTLY_CLOUDY`, use the selected local date's supplied sunrise/sunset to choose day artwork from sunrise minus one hour inclusive to sunset minus one hour exclusive; explicit typed identities stay explicit. Older recordings can display from broad conditions without claiming a typed supplied fact. Scene light timing and timeline gestures do not change.

`OpenMeteoTransport` exposes the exact bounded response bytes, parsed JSON from those bytes, request identity, and retrieval time on success. `OpenMeteoCatalogSource` maps that capture to the existing 44-local-date catalog (D-30..D-1 and D..D+13 relative to `asOf`), preserving provider gaps and DST, and passes the unchanged capture alongside success/partial results. No second fetch or JSON reserialization substitutes for original bytes. Scene/view consume catalog facts, never raw JSON. Expand the board's grouped WMO ledger into exact accepted codes and unsupported intermediate cases before mapper changes; implement documented Sky assignments now and keep preexisting non-Sky broad behavior until its row slice. Code descriptions come from that fixed ledger, never from a claimed provider response string.

New `RecordedCatalogCodec` payloads use schema version 5 with optional typed events, member-referenced primary, and recording-level raw response attachment containing exact bytes, request identity, provider, retrieval time, and our separately named capture-contract version. Preserve version 1–4 decoding and broad facts without backfilling absent typed data or raw response. `CatalogDatasetStorage` must admit every codec-supported payload version through 5 while retaining row/payload identity checks; versions 3–4 must load. The opaque Room row does not require a database table migration unless implementation reveals an actual table change. Both `CatalogRefreshPolicy` and `CatalogActivationCoordinator` recording constructors carry the same optional live capture. Cached/simulated/replay paths do not fabricate one; a later live fetch creates a new recording. Keep storage `storedAt`, provider retrieval time, and catalog `asOf` distinct.
