## Canonical and authoring type contract

- `CanonicalWeatherFacts` is the existing canonical fact type. It has one absolute `validTime: Instant` and the supported typed weather fields for that instant. It does not contain an expected-support map. In this DFM.4.5 SIMULATED catalog, the source supplies one such fact for each real local-hour instant; DST dates therefore have 23 or 25 facts. A nonexistent local hour has no fact.
- `CanonicalCatalog` is the catalog snapshot: fixed `CatalogLocation` (including IANA timezone), `DatasetId`, provenance, `asOf`, ordered `facts`, product segments, and daily summaries. `CatalogRecording` pairs it with `expectedSupport` and `dailyExpectedSupport`; those maps describe point/interval coverage separately from fact values. Preserve all three types and their existing boundaries; do not add a second hourly-fact type or move support into `CanonicalWeatherFacts`.
- An **Authored Envelope** is the editor's outer half-open local wall-time interval `[startLocal, endLocalExclusive)`, represented by local date-times and interpreted in the catalog's fixed timezone. It limits where the user may place authored instructions; it is not itself a weather value and does not shorten catalog coverage. It must be nonempty, fit the canonical horizon, and include at least one real fact.
- An **Authored Event** is one debug-only editor instruction, not a meteorological event object and not a canonical fact. It consists of exactly one **Event Range** and one complete `DebugAuthoredWeatherValues`-shaped value object using only existing canonical fields. There is no separate event-type enum or new weather taxonomy. `WeatherCondition` and `WeatherPhenomenon` remain values inside that object.
- An **Event Range** is the single half-open local wall-time interval `[eventStartLocal, eventEndLocalExclusive)` owned by its Authored Event. It is not a separate weather record and does not identify one unique offset occurrence. Compare each real fact's local date-time in the catalog timezone with this interval: include it when `eventStartLocal <= localDateTime < eventEndLocalExclusive`. Thus both real instants in a repeated hour are included; a gap hour contributes no fact. Require whole-hour boundaries, containment by the Authored Envelope, and at least one covered real fact. A single Authored Event cannot have disjoint ranges; use a separate event for each interval.
- The event value object is field-complete, not value-complete: every existing canonical field has a value or an unavailable representation (`null` for nullable measurements; an empty set for conditions/phenomena). Applying an event **replaces the full weather-value set** on each covered baseline fact while preserving its `validTime`; it never merges with baseline values. `null` and empty sets mean unavailable/not supplied, never “inherit baseline.” Explicit numeric zero is a supplied value. Expected support is then derived from the materialized facts using the existing point/interval support rules. Outside all Event Ranges, including uncovered portions of the Authored Envelope, retain the deterministic SIMULATED baseline unchanged.
- Authored Events are ordered by their local start boundary. Their ranges may be adjacent (`previous.end == next.start`) but may not overlap (`previous.end > next.start`). No fact can therefore receive two authored instructions. The sidecar stores the ordered event definitions/ranges and complete value objects, bound to the canonical recording hash. For REPLAY, retained definitions describe captured origin only; they do not make the immutable snapshot editable.
- A **Catalog Library Item** is the mutable local name and reference to its current SIMULATED `DatasetId`; it is not a canonical catalog or recording. Each saved SIMULATED revision is an immutable `CatalogRecording` under a fresh dataset identity. An edit writes the new recording and matching sidecar first, then changes the item's reference. A **REPLAY snapshot** is a separate immutable recording identity in the REPLAY namespace, copying the saved canonical facts and retaining `CatalogProvenance.origin = SIMULATED` as captured origin. The existing coordinator's selected REPLAY projection identifies it as replay during preview. It is previewable but never editor input.

The approved boards' words “event” and “range” refer to these editor-instruction and interval concepts. This contract clarifies their existing behavior and uses the repository's existing canonical types; it does not change the approved UI flow, storage/schema boundary, or acceptance scope.

## Scope and functional invariants

- The canonical weather-fact unit is `CanonicalWeatherFacts`, one value per absolute valid time. For this synthetic source there is exactly one per real local-hour instant, with its timestamp and typed weather fields. Catalog-level identity/provenance and ordered facts remain in `CanonicalCatalog`; expected point/interval support remains in `CatalogRecording`. Preserve each boundary and the full 44-local-date horizon.
- Preserve the canonical D−30…D+13 local-date horizon. Each date has 23, 24, or 25 real hourly facts as determined by its timezone and DST transition; do not treat the nominal 44×24 count as the canonical shape.
- An Authored Event is one editor instruction with exactly one Event Range and one field-complete `DebugAuthoredWeatherValues` object. It is not a canonical weather event or record. Its Event Range is a half-open local wall-time interval within the Authored Envelope, interpreted in the fixed catalog timezone. See the canonical and authoring type contract above for complete replacement, missingness, DST, and ordering semantics.

- In an active debug session, `#PICKER` opens the local catalog library. Outside that session, it remains ordinary location search and dispatches no developer UI.
- Provide named SIMULATED create/edit/save/reopen workflows. Choose a fixed-location Authored Envelope first, then add Authored Events, each with exactly one typed value object and one half-open Event Range inside the envelope. Require whole-local-hour boundaries, at least one real covered `CanonicalWeatherFacts` per event, and non-overlap; reject ranges that cover no fact, including ranges entirely inside a DST gap. Carry forward the DFM.4 owner decision to reject conflicting ranges. Uncovered facts inside the envelope retain deterministic SIMULATED baseline values. Display and retain catalog-level fixed location identity and IANA timezone.
- Editing a logical SIMULATED library item must honor DFM.4.4's immutable dataset identities. Treat the library item as a reference to its current immutable canonical catalog revision. On save, write the edited canonical catalog under a fresh dataset identity, persist its matching metadata, and only then update that item's reference. If either write fails, leave the prior item and revision intact; cancel discards the draft. Do not mutate an existing canonical recording or a REPLAY snapshot in place.
- Preserve the complete canonical D−30…D+13 catalog coverage in `CanonicalCatalog.facts`, with deterministic baseline values outside authored Event Ranges and in uncovered parts of the Authored Envelope. For each covered fact, replace the whole weather-value set from its event's field-complete value object; null/empty values remain unavailable rather than inheriting baseline data. Keep probability separate from amount and unsupported conditions absent. Both real facts in a repeated local hour are covered when their local times fall in range; nonexistent DST-gap instants have no fact.
- Version the debug-only metadata sidecar for an ordered list of Authored Events, each with one Event Range and complete value object, bound to the canonical catalog recording hash. Reopen an existing DFM.4.4 period-wide SIMULATED or REPLAY sidecar as one Authored Event whose range and envelope both equal the former authored period, preserving its period-wide replacement values; REPLAY definitions remain provenance only and cannot be edited. Do not change canonical schema, codec, Room schema, or storage namespaces.
- Saving creates or updates only the local editable SIMULATED record. Save and Capture REPLAY never activate. Cancel discards the unsaved draft and leaves any previously saved item unchanged.
- Capture REPLAY from a saved SIMULATED record as a distinct immutable snapshot preserving captured facts and SIMULATED origin. REPLAY has Preview only and cannot be edited or overwritten.
- Preview is a separate explicit action from a saved record only. Revalidate the saved SIMULATED or REPLAY record through the existing DFM.4.4 validation boundary, then activate through its coordinator-selected-time path. Make synthetic origin discoverable and never label it LIVE.
- If a saved record is missing, invalid, changed, or mismatched, show an actionable failure and remain in the workflow; preserve the current active catalog and selected instant without fallback content.
- Keep debug-session exit and ordinary-action ordering: restore the exact pre-session catalog and selected instant without I/O before ending debug or performing ordinary location/refresh actions.
- Do not mutate provider, LIVE, cache, location, or saved-place state. Preserve normal forecast composition, weather facts, timeline behavior, and ordinary location paths.
