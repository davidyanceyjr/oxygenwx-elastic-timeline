## Invariants and boundaries

- Main source uses generic hooks, with no developer command names or parsing; release has no command handler/provider. Exact commands use the existing trimmed search submission, without case folding or substring matching. Unconsumed queries retain ordinary behavior; consuming a command invalidates stale search work.
- `#DEBUG` in debug waits for coordinator startup readiness and a settled activation, captures the opaque checkpoint and opens the session without geocoding, refresh or selection change. Pending entry is not an active session. `#PICKER` follows ordinary search outside an active session; in an active session it opens the existing forecast picker. The new catalog library is DFM.4.5.
- Exit restores the checkpoint and exact selected instant without I/O. Before ordinary selection persistence or refresh/retry, cancel pending entry, restore and end the session, then run the ordinary action once. Failed actions leave debug off; stale completions cannot overwrite the action. Empty/error retry follows the same boundary.
- Preserve canonical forecast semantics, source and storage behavior, selected-time authority, responsiveness, gesture ownership and readability. Debug entry does not mutate provider, cache or location state; ordinary actions retain their existing effects after restoration.
- Selecting a search result or a previously selected location saves it if necessary, selects and loads it, closes the location menu, and returns to the main view. Selected locations remain in a persistent list beneath the search input until removed through the existing remove action. Reopening the menu begins another interaction; it does not undo the selection. Preserve existing removal confirmation and failure handling. If selection cannot be saved, retain a visible failure rather than claim it loaded.

## Resolved lifecycle and picker contracts

These contracts follow the approved session-flow amendment and cycle 084's archived restoration contract; cycle 085 evidence establishes the coordinator APIs, not completion of this session wiring.

| State / input | Required transition |
|---|---|
| Normal + `#DEBUG` | Consume the trimmed exact command, invalidate prior search, start one lifecycle-scoped pending entry, and wait for `captureSettledCheckpoint()`. Do not interrupt startup or an activation. |
| Pending + ordinary selection or forecast refresh/retry | Invalidate/cancel the entry continuation before the ordinary action; no checkpoint is restored and startup remains coordinator-owned. A late capture must not open the menu. `#PICKER` remains ordinary search. |
| Pending + successful capture | Recheck that the same entry is still eligible before retaining the opaque checkpoint and opening the active session. Settled empty and error states are valid; do not retry or invent an active catalog. |
| Active + explicit exit or ordinary action | Invalidate session-owned entry, picker and preview continuations; restore the saved checkpoint once, clear overlay/session state and discard the checkpoint before continuing. Explicit exit ends there. For an ordinary action, only after the callback completes successfully perform the original action once; a subsequent failure keeps debug off and does not restore again. |
| Normal + ordinary action | Cancel any pending entry if present; otherwise the callback is a no-op. Release has no delegate and retains its original action. Editing queries, opening the selector, and ordinary search do not end a session. |

`CatalogActivationCoordinator.captureSettledCheckpoint()` atomically checks both startup participation and terminal activation under its synchronization boundary; it suspends without holding that boundary. `restoreCheckpoint()` synchronously advances request sequencing, cancels the in-flight request, completes its handle as superseded, restores the saved state and assigns a fresh view generation. Do not await while holding coordinator synchronization, rebase checkpoints, restore counters, reconstruct state with I/O, or create a second activation owner. Coordinate session invalidation and checkpoint ownership so an ordinary action cannot race a late entry/exit into restoring over that action. Host cancellation must not open a picker, trigger fallback or falsely signal startup readiness; preserve cancellation propagation and cycle 085's alternate cold-launch handshake.

The existing action seams are `LocationSelectorController.select()`'s `beforeSelection` before `store.select`, and both active-forecast refresh and empty/error retry in `MainActivity` before `refreshCurrent()`. The latter uses the coordinator's `lastRequest`, so restoration must precede the refresh. Existing hooks are unaccepted scaffolding: verify their ordering and failure paths rather than assuming they meet the contract.

The existing catalog picker is `CatalogPickerDelegate.openCatalogPicker()` → `DebugCatalogActivity`, not the separate legacy `DebugForecastActivity` (which that picker can launch). Its selection returns `ACTION_ACTIVATE_CATALOG` or `ACTION_SELECT_CATALOG_INSTANT` to `MainActivity`; the delegate validates and executes these asynchronously. Active-session `#PICKER` must reach this existing picker, and entry/exit must preserve the independently existing debug cold-launch and request behavior. Session-originated picker callbacks and request continuations must be invalidated on exit or before ordinary actions, including requests delayed before coordinator submission, so a late result cannot start an activation, select an instant, reopen the picker or restore old state over the ordinary action. Coordinator sequence and view-generation guards alone do not protect a request that has not yet been submitted. Preserve existing non-session debug paths and failure/cancellation handling. If the existing picker cannot be integrated with those guarantees without expanding scope or weakening its established behavior, stop and replan rather than silently dropping picker dispatch or the restoration guarantee.
