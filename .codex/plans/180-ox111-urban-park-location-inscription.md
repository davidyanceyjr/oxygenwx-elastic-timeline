## Shared contract, invariants, and exclusions

- The app resolves forecast and selected-time decisions before rendering. :scene-core receives a theme-neutral scene description and generic Compose/rendering callbacks only; it does not import provider DTOs, forecast presentation types, SceneWeatherDecision, or app/theme names. :app depends on :scene-core one way.
- App-owned theme definitions retain weather mapping, selected-time authority, theme selection, assets, geometry/material descriptions, and custom painters. The core supplies ordered entries, the optional shared plane stack, and painted-data-surface rendering in the slices that need them.
- Preserve current visible appearance, forecast mapping, source-time meaning, selected instant, picker action, remaining meteo readout, main data viewer, and timeline behavior throughout the adapters. First City retains default, baseline-proof, olive, and installed-content behavior. First City, Living Urban Park, and Open Landscape retain central location labels. Only OX-111E moves the visible Urban Park location name.
- Urban Park keeps OX-99 plane alignment/alpha and OX-110 underlay, celestial, cloud, Middleground/tree, and Foreground/banner ordering. Plane draws remain separately ordered so stars, Sun/Moon, clouds, and inscription can interleave. The tower face uses the same Park viewport transform before local treatment.
- Chicago is one painted line; San Francisco wraps at a word boundary on the same face. Text is dynamic, clipped, transformed, and integrated with theme-provided pigment/lighting; blank input draws no inscription. Canvas text remains decorative, with selected-location semantics outside Canvas.
- A future code-backed Kotlin/Compose theme can supply its own planes, ordered elements, geometry, materials, and painters. This cycle adds no new themes, theme SDK/schema, location/network behavior, other migrated meteo fields, or broad RTL/TalkBack/system acceptance.
